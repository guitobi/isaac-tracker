Урок 1: Архітектура Prisma в NestJS

Привіт! Оскільки ви вже є fullstack розробником, ми пропустимо пояснення того, що таке ORM. Давайте одразу сфокусуємось на тому, як NestJS та Prisma "спілкуються" між собою.

Проблема: Інстанс Prisma Client

Prisma генерує клас PrismaClient. Щоб працювати з базою даних, нам потрібен його екземпляр. Але NestJS працює на базі Dependency Injection (Впровадження залежностей). Якщо ми будемо просто робити new PrismaClient() у кожному файлі, ми втратимо контроль над пулом з'єднань і порушимо архітектуру Nest.

Рішення: PrismaService

Щоб інтегрувати Prisma "по-нестівськи", ми створюємо сервіс (провайдер), який розширює базовий клієнт. Цей сервіс потім можна інжектити в будь-який інший сервіс або контролер (наприклад, у ваш RunsService).

import { Injectable, OnModuleInit } from '@nestjs/common';
import { PrismaClient } from '@prisma/client';

@Injectable()
export class PrismaService extends PrismaClient implements OnModuleInit {
  async onModuleInit() {
    // Встановлюємо з'єднання з БД при старті додатка
    await this.$connect();
  }
}

Джерело: Офіційна документація NestJS (Prisma Recipes)

Цей код робить три речі:

  1. Декоратор @Injectable() дозволяє інжектити цей клас в інші частини додатка.
  2. Розширення (extends) від PrismaClient означає, що PrismaService отримує всі методи для роботи з БД (наприклад, this.user.findMany()).
  3. Реалізація OnModuleInit дозволяє підключитися до бази даних ($connect()) безпосередньо під час ініціалізації модуля NestJS, що є найкращою практикою.
