Урок 7: Інтеграція сервісів та збереження забігу

Вітаю! Ви успішно навчилися парсити сід та персонажа з лог-файлу гри. Тепер прийшов час об'єднати це з базою даних.

1. Зв'язок між сервісами (Dependency Injection)

Щоб зберегти забіг, нашому LogReaderService потрібно викликати метод create() з RunsService. Для цього ми маємо впровадити RunsService через конструктор:

constructor(private readonly runsService: RunsService) {}

Важливо: Оскільки ми імпортуємо сервіс з іншого модуля, нам потрібно переконатися, що RunsModule експортує свій RunsService, а AppModule (або модуль лог-рідера) імпортує RunsModule. Але оскільки ми зареєстрували LogReaderService прямо в AppModule в полі providers, а RunsModule імпортований в imports, нам достатньо просто додати exports: [RunsService] у RunsModule.

2. Збереження забігу при старті

Оскільки гра логує сід та ініціалізацію персонажа в різних рядках (але майже одночасно), нам потрібно зберегти ці дані в пам'яті сервісу, поки ми не отримаємо обидва значення.

Для цього ми можемо створити локальні змінні класу LogReaderService:

private currentSeed: string | null = null;

Коли ми знаходимо сід — записуємо його в currentSeed. А коли гра повідомляє про ініціалізацію персонажа (Variant), ми беремо цей сід, мапимо варіант персонажа на ID в БД і викликаємо runsService.create()!

Мапінг персонажів:

У базі даних у нас є персонажі, створені сід-скриптом (дефолтний порядок ID: 1 - Isaac, 2 - Magdalene, 3 - Cain, 4 - Judas). В грі вони мають Variant ID (0 - Isaac, 1 - Magdalene, 2 - Cain, 3 - Judas). Ми можемо зробити простий мапінг:

const characterMap: Record = {
  0: 1, // Variant 0 -> Character ID 1 (Isaac)
  1: 2, // Variant 1 -> Character ID 2 (Magdalene)
  2: 3, // Variant 2 -> Character ID 3 (Cain)
  3: 4, // Variant 3 -> Character ID 4 (Judas)
};

Створення запису:

Оскільки в нашій схемі Run поля isVictory (Boolean) та duration (Int) є обов'язковими, при старті забігу ми можемо передати дефолтні значення:

this.runsService.create({
  seed: seed,
  characterId: characterId,
  userId: 1, // ID нашого дефолтного користувача Player
  isVictory: false,
  duration: 0,
});
Перевірка знань: Що потрібно зробити в `RunsModule` (`runs.module.ts`), щоб його сервіс `RunsService` став доступним для інших модулів/провайдерів в `AppModule`?

Ваше практичне завдання:

Пишіть код самостійно!

  1. У файлі src/runs/runs.module.ts додайте exports: [RunsService] у декоратор модуля, щоб інші могли ним користуватися.
  2. У файлі src/log-reader/log-reader.service.ts:
    • Додайте конструктор та впровадьте RunsService.
    • Створіть приватну змінну класу currentSeed: string | null = null; для тимчасового зберігання сіду в пам'яті.
    • Коли знаходите сід — зберігайте його в this.currentSeed.
    • Коли знаходите персонажа (Variant) — отримайте збережений сід, знайдіть відповідний `characterId` за допомогою `characterMap` і викличте this.runsService.create(). Після створення забігу не забудьте обнулити this.currentSeed = null;.

Коли оновите код — запустіть гру, почніть новий раунд. Перевірте консоль на наявність помилок, а потім перевірте вашу базу даних (або зробіть GET запит на http://localhost:3000/runs), щоб переконатися, що раунд зберігся! Напишіть "готово", коли все вийде.
