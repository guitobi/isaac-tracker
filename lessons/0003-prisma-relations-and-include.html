Урок 3: Робота зі зв'язками (Relations)

Чудово, ви написали свій перший запит! Але зараз findAll() повертає лише "плоскі" дані про забіги (id, seed, duration, userId, characterId). А що, якщо для клієнта (фронтенду) потрібно віддати ще й ім'я персонажа та ім'я гравця?

Магія Prisma: include

В інших ORM вам часто доводиться писати складні JOIN-запити або налаштовувати "eager/lazy loading". У Prisma все набагато простіше та абсолютно типізовано. Для того, щоб отримати пов'язані дані, ми використовуємо ключове слово include.

Погляньте на ваш файл schema.prisma. У моделі Run є поля-зв'язки:

model Run {
  ...
  user        User      @relation(fields: [userId], references: [id])
  character   Character @relation(fields: [characterId], references: [id])
}

Щоб "дістати" ці дані при запиті, ми передаємо об'єкт конфігурації у метод findMany():

async findAll() {
  return this.prisma.run.findMany({
    include: {
      user: true,      // Додає об'єкт користувача в результат
      character: true, // Додає об'єкт персонажа в результат
    }
  });
}

Найкрутіше те, що TypeScript миттєво зрозуміє це! Тип результату зміниться, і ви (або ваш фронтенд) будете знати, що у об'єкті Run тепер гарантовано є вкладені поля user.username та character.name.

Джерело: Документація Prisma Relation Queries

Перевірка знань: Що станеться, якщо ми НЕ використаємо `include`, але спробуємо звернутися до `run.user.username` у нашому коді після запиту?

Ваше практичне завдання:

  1. Оновіть ваш метод findAll() у runs.service.ts так, щоб він використовував include для підвантаження і користувача, і персонажа.
  2. (За бажанням) Спробуйте після `include` поставити кому і додати `orderBy: { duration: 'desc' }` — це відсортує забіги за тривалістю!
